# Rules: TypeScript, code style and language (R-TS)

Formatting and linting are decided by Prettier + ESLint (`.prettierrc.json`, `eslint.config.mjs`). This file only covers what the tools cannot catch.

| ID     | Level  | Rule                                                                                                                                                                                                                     | Why                                                        | Verified by      |
| ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- | ---------------- |
| R-TS-1 | MUST   | Keep `strict`. No `any`, no `@ts-ignore`; `@ts-expect-error` only with a reason on the same line.                                                                                                                        | Types are the living documentation of contracts.           | `tsc`, `lint`    |
| R-TS-2 | MUST   | External data (Server Action input, `searchParams`, backend responses, env) is `unknown` until it passes Zod `safeParse`/`parse`. Domain types are inferred from schemas (`z.infer`), never written by hand in parallel. | Clear trust boundaries; types never drift from validation. | `review`, `test` |
| R-TS-3 | MUST   | Do not use type assertions (`as`) to silence type errors. `as` is acceptable only right after a runtime check, or to narrow a literal (`as const`).                                                                      | `as` switches the checker off.                             | `review`         |
| R-TS-4 | MUST   | Results with several states use discriminated unions (e.g. `ActionResult = { ok: true } \| { ok: false; error; fieldErrors? }`).                                                                                         | The compiler forces every branch to be handled.            | `tsc`            |
| R-TS-5 | MUST   | Handle every error path: network, parsing, external calls. A deliberate skip needs a `// skip: <reason>` comment. No silent `catch {}`.                                                                                  | Swallowed errors cannot be debugged.                       | `review`         |
| R-TS-6 | SHOULD | Prefer readable types over complex type-level code (nested conditional/mapped types).                                                                                                                                    | Readers include backend developers new to frontend.        | `review`         |
| R-TS-7 | SHOULD | kebab-case file names (`search-input.tsx`), PascalCase components, named exports. Comments explain **why**.                                                                                                              | Consistent with the existing code.                         | `review`         |
| R-TS-8 | MUST   | Write code comments, documentation, rules and skills in **English**. The only Vietnamese file is `README.vi.md`, which must stay in sync with `README.md`.                                                               | One language for every reader and every agent.             | `review`         |
