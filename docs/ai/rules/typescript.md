# Rules: TypeScript và code style (R-TS)

Format và lint do Prettier + ESLint quyết định (`.prettierrc.json`, `eslint.config.mjs`). File này chỉ ghi những gì công cụ không bắt được.

| ID     | Mức    | Quy tắc                                                                                                                                                                                                         | Lý do                                                      | Kiểm chứng       |
| ------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------- |
| R-TS-1 | MUST   | `strict` giữ nguyên. Không `any`, không `@ts-ignore`; `@ts-expect-error` chỉ kèm lý do trên cùng dòng.                                                                                                          | Type là tài liệu sống của contract.                        | `tsc`, `lint`    |
| R-TS-2 | MUST   | Dữ liệu từ ngoài (input Server Action, `searchParams`, response backend, env) có kiểu `unknown` cho tới khi đi qua Zod `safeParse`/`parse`. Type domain suy ra từ schema (`z.infer`), không viết tay song song. | Ranh giới tin cậy rõ ràng; type không lệch với validation. | `review`, `test` |
| R-TS-3 | MUST   | Không ép kiểu (`as`) để che lỗi type. Chấp nhận `as` chỉ khi đã kiểm tra bằng runtime ngay trước đó hoặc thu hẹp một literal (`as const`).                                                                      | `as` tắt bộ kiểm tra.                                      | `review`         |
| R-TS-4 | MUST   | Kết quả có nhiều trạng thái dùng discriminated union (ví dụ `ActionResult = { ok: true } \| { ok: false; error; fieldErrors? }`).                                                                               | Compiler buộc xử lý mọi nhánh.                             | `tsc`            |
| R-TS-5 | MUST   | Mọi đường lỗi được xử lý: network, parse, external call. Bỏ qua có chủ đích phải có comment `// skip: <lý do>`. Không `catch {}` im lặng.                                                                       | Lỗi bị nuốt là lỗi không debug được.                       | `review`         |
| R-TS-6 | SHOULD | Ưu tiên type dễ đọc hơn type-level phức tạp (conditional/mapped type lồng nhau).                                                                                                                                | Người đọc là backend developer mới làm frontend.           | `review`         |
| R-TS-7 | SHOULD | Tên file kebab-case (`search-input.tsx`), component PascalCase, named export. Comment chỉ giải thích **vì sao**.                                                                                                | Nhất quán với code hiện có.                                | `review`         |
