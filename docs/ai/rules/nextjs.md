# Rules: Next.js (R-NX)

Applies to `src/app/**` and every component rendered in a route. The installed version is **Next.js 16.4** (App Router, `cacheComponents`, `partialPrefetching`).

**Before using any Next.js API, read its guide in `node_modules/next/dist/docs/`**: this version differs from older knowledge (for example `next lint` is gone, `middleware` is now `proxy`, `params`/`searchParams` are Promises).

**Verified by** column: `tsc` / `lint` / `test` / `e2e` / `build` = automated; `review` = checked by an agent or reviewer; `human` = a human decision.

| ID      | Level  | Rule                                                                                                                                                                                                                                                                                 | Why                                                                                                                                | Verified by                               |
| ------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| R-NX-1  | MUST   | `src/app/` only holds routing: `page`, `layout`, `error`, `not-found`, `loading`, `route`, metadata. Reusable components live in `src/components/`; business code in `src/features/`.                                                                                                | Routes compose; they do not hold logic.                                                                                            | `review`                                  |
| R-NX-2  | MUST   | Server Component by default. Add `'use client'` only when the file uses state, effects, event handlers or browser APIs. Put `'use client'` on interactive **leaves**, never on a page or layout.                                                                                     | Less JavaScript shipped to the client; streaming and PPR keep working.                                                             | `review`                                  |
| R-NX-3  | MUST   | Client Components do not import `server-only` modules (`@/lib/env`, `@/lib/auth`, `@/lib/api/backend`, `services/*`). Code that runs on both sides has no `'use client'` and imports nothing `server-only`.                                                                          | Keeps secrets out of the browser bundle.                                                                                           | `build` (server-only throws)              |
| R-NX-4  | MUST   | Props passed from a Server to a Client Component are serializable: pass elements (`icon={<Plus />}`), not components or functions (except Server Actions).                                                                                                                           | RSC only serializes plain data.                                                                                                    | `build`, `review`                         |
| R-NX-5  | MUST   | Read dynamic data (repository, `cookies()`, `searchParams`, session) inside `<Suspense>`. A page without a request-time API calls `await connection()` **before** reading data or the session.                                                                                       | With Cache Components, data read outside Suspense or before a request-time API is prerendered into the static shell at build time. | `build` (route must be `◐`/`ƒ`), `review` |
| R-NX-6  | MUST   | Do not add `'use cache'`, `cacheLife` or `cacheTag` without a measured reason. When you do: never put per-user data or secrets in a cache key, and mutations must call the matching `updateTag`/`revalidateTag`.                                                                     | Wrong caching leaks data between users or serves stale data.                                                                       | `review`, `human`                         |
| R-NX-7  | MUST   | Mutations go through a Server Action in `src/features/<f>/actions.ts`, followed by `revalidatePath` (or a tag) for the affected routes.                                                                                                                                              | One write path, easy to protect.                                                                                                   | `test`                                    |
| R-NX-8  | MUST   | Every data screen has a loading state (Suspense fallback/skeleton), an empty state and an error state (`error.tsx` or an inline error from `ActionResult`).                                                                                                                          | No screen goes blank when slow, empty or failing.                                                                                  | `e2e`, `review`                           |
| R-NX-9  | MUST   | Use framework APIs: the Metadata API for title/description, `next/link` for internal navigation, `redirects()` in `next.config.ts` for static redirects, `next/font` for fonts. Do not use experimental APIs (`unauthorized()`, `forbidden()`, `authInterrupts`) without a decision. | Stable across version upgrades.                                                                                                    | `review`                                  |
| R-NX-10 | MUST   | A Server Action is a public POST endpoint: follow R-SEC-1…R-SEC-4.                                                                                                                                                                                                                   | Hiding a button in the UI protects nothing.                                                                                        | `test`                                    |
| R-NX-11 | SHOULD | Fetch in parallel with `Promise.all` when data sources are independent.                                                                                                                                                                                                              | Avoids waterfalls.                                                                                                                 | `review`                                  |
| R-NX-12 | SHOULD | Keep filters, search and pagination in the URL (`searchParams`), not in global state.                                                                                                                                                                                                | Shareable links; correct server rendering.                                                                                         | `review`                                  |
| R-NX-13 | MAY    | Add `loading.tsx` when you want a fallback for the whole segment; by default use Suspense inside the page so the static shell shows immediately.                                                                                                                                     | Both are valid.                                                                                                                    | `human`                                   |

Detailed explanation and diagrams: [`docs/architecture.md`](../../architecture.md) sections 5–6.
