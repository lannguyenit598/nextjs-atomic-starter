# Rules: Security (R-SEC)

Detailed auth contract: [`docs/api-integration.md`](../../api-integration.md) section 8. History and evidence: [`docs/audits/production-readiness-audit.md`](../../audits/production-readiness-audit.md).

| ID       | Level  | Rule                                                                                                                                                                                                                                                                                                                                        | Why                                                            | Verified by                                    |
| -------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------- |
| R-SEC-1  | MUST   | Every Server Action calls `await requireSession('<feature>:write')` as the **first line** inside `try`, before validation and before any data access. Errors go through `toActionFailure()`.                                                                                                                                                | Server Actions are public POST endpoints.                      | `test` (signed-out + missing-permission cases) |
| R-SEC-2  | MUST   | Pages reading protected data: read request-time data first, then `getSession()`: no session → "Sign-in required", `!hasPermission(session, '<feature>:read')` → "Permission required". REST read methods call `requireSession('<feature>:read')`; a repository that does not go through `backendRequest()` calls `requireSession()` itself. | Hiding UI or redirecting is not protection.                    | `review`, `test`                               |
| R-SEC-3  | MUST   | REST mode is **fail-closed**: `resolveSession()` returns `null` by default; `backendRequest()` always calls `requireSession()` before `fetch`. Never relax these "for convenience".                                                                                                                                                         | Anonymous visitors must not borrow `API_TOKEN`.                | `test` (`backend.test.ts`, `auth.test.ts`)     |
| R-SEC-4  | MUST   | All untrusted input goes through Zod. Ids interpolated into backend URLs use the allowlist `^[A-Za-z0-9_-]{1,100}$` (never `typeof id === 'string'`).                                                                                                                                                                                       | Blocks path traversal (`.`, `..`, `/`).                        | `test`                                         |
| R-SEC-5  | MUST   | Secrets live only in server env (no `NEXT_PUBLIC_` prefix) and are read only through `@/lib/env` (which has `import 'server-only'`). New files using secrets add `import 'server-only'`.                                                                                                                                                    | Secrets never reach the bundle.                                | `build`, `review`                              |
| R-SEC-6  | MUST   | `AUTH_ALLOW_ANONYMOUS` defaults to `false`. Never enable it in `.env.example`, CI, E2E tests or production guides.                                                                                                                                                                                                                          | The flag gives every visitor the full power of `API_TOKEN`.    | `review`, `test` (`env.test.ts`)               |
| R-SEC-7  | MUST   | Never log or return to the client: tokens, secrets, backend 5xx bodies, stack traces. User-facing errors go through `toActionFailure()` (only messages of `VALIDATION_ERROR`, `NOT_FOUND`, `TIMEOUT`, `NETWORK_ERROR` pass through).                                                                                                        | Prevents leaking internals.                                    | `test`, `review`                               |
| R-SEC-8  | MUST   | Keep the CSP and security headers in `next.config.ts`. Add external origins (analytics, CDN) only when needed, with a written reason. No `dangerouslySetInnerHTML` with dynamic data.                                                                                                                                                       | Keeps the XSS/clickjacking protection.                         | `e2e` (CSP fixture + `security.spec.ts`)       |
| R-SEC-9  | MUST   | Do not build a sign-in system or install auth libraries without concrete backend requirements. Integrate through `resolveSession()` in `src/lib/auth-provider.ts`.                                                                                                                                                                          | Auth depends on the backend; a wrong guess is worse than none. | `human`                                        |
| R-SEC-10 | SHOULD | `resolveSession()` returns the user's `accessToken` so the backend can enforce data ownership itself.                                                                                                                                                                                                                                       | Otherwise every user shares the service account (IDOR).        | `review`                                       |
| R-SEC-11 | SHOULD | Every security-related change has at least one **negative test** (signed out, missing permission, malicious input).                                                                                                                                                                                                                         | Proves the guard actually blocks.                              | `test`                                         |
