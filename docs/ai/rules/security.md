# Rules: Security (R-SEC)

Contract auth chi tiết: [`docs/api-integration.md`](../../api-integration.md) mục 8. Lịch sử và bằng chứng: [`docs/audits/production-readiness-audit.md`](../../audits/production-readiness-audit.md).

| ID       | Mức    | Quy tắc                                                                                                                                                                                                                     | Lý do                                                        | Kiểm chứng                                 |
| -------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------ |
| R-SEC-1  | MUST   | Mỗi Server Action gọi `await requireSession('<feature>:write')` là **dòng đầu tiên** trong `try`, trước validate và trước mọi truy cập dữ liệu. Lỗi trả qua `toActionFailure()`.                                            | Server Action là endpoint POST công khai.                    | `test` (case chưa đăng nhập + thiếu quyền) |
| R-SEC-2  | MUST   | Page đọc dữ liệu được bảo vệ: đọc request-time data trước, rồi `if (!(await getSession()))` hiển thị "Sign-in required". Repository không đi qua `backendRequest()` phải tự gọi `requireSession()`.                         | Ẩn UI hay redirect không phải là bảo vệ.                     | `review`, `test`                           |
| R-SEC-3  | MUST   | REST mode **fail-closed**: `resolveSession()` mặc định trả `null`; `backendRequest()` luôn gọi `requireSession()` trước `fetch`. Không nới các điểm này để "cho tiện".                                                      | Visitor ẩn danh không được mượn `API_TOKEN`.                 | `test` (`backend.test.ts`, `auth.test.ts`) |
| R-SEC-4  | MUST   | Mọi input không tin cậy đi qua Zod. Id ghép vào URL backend dùng allowlist `^[A-Za-z0-9_-]{1,100}$` (không dùng `typeof id === 'string'`).                                                                                  | Chặn path traversal (`.`, `..`, `/`).                        | `test`                                     |
| R-SEC-5  | MUST   | Secret chỉ ở env server (không prefix `NEXT_PUBLIC_`), chỉ đọc qua `@/lib/env` (có `import 'server-only'`). File mới dùng secret phải có `import 'server-only'`.                                                            | Không lộ secret vào bundle.                                  | `build`, `review`                          |
| R-SEC-6  | MUST   | `AUTH_ALLOW_ANONYMOUS` mặc định `false`. Không bật trong `.env.example`, CI, test E2E hay tài liệu hướng dẫn production.                                                                                                    | Cờ này trao toàn quyền `API_TOKEN` cho mọi visitor.          | `review`, `test` (`env.test.ts`)           |
| R-SEC-7  | MUST   | Không log, không trả về client: token, secret, body lỗi 5xx của backend, stack trace. Lỗi cho người dùng đi qua `toActionFailure()` (chỉ cho phép message của `VALIDATION_ERROR`, `NOT_FOUND`, `TIMEOUT`, `NETWORK_ERROR`). | Chặn lộ thông tin nội bộ.                                    | `test`, `review`                           |
| R-SEC-8  | MUST   | Giữ CSP và security headers trong `next.config.ts`. Thêm origin bên ngoài (analytics, CDN) chỉ khi cần và ghi lý do. Không thêm `dangerouslySetInnerHTML` với dữ liệu động.                                                 | Giữ lớp bảo vệ XSS/clickjacking.                             | `e2e` (fixture CSP + `security.spec.ts`)   |
| R-SEC-9  | MUST   | Không tự viết hệ thống đăng nhập, không cài thư viện auth khi chưa có yêu cầu backend cụ thể. Tích hợp qua `resolveSession()` trong `src/lib/auth-provider.ts`.                                                             | Cơ chế auth phụ thuộc backend; đoán sai còn tệ hơn không có. | `human`                                    |
| R-SEC-10 | SHOULD | `resolveSession()` trả `accessToken` của user để backend tự kiểm tra quyền sở hữu dữ liệu.                                                                                                                                  | Nếu không, mọi user dùng chung service account (IDOR).       | `review`                                   |
| R-SEC-11 | SHOULD | Mỗi thay đổi liên quan bảo mật có ít nhất một **negative test** (chưa đăng nhập, thiếu quyền, input độc hại).                                                                                                               | Chứng minh guard thật sự chặn.                               | `test`                                     |
