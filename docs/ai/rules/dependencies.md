# Rules: Dependencies (R-DEP)

The approved baseline and the reason for every package: [`docs/audits/dependency-deep-audit.md`](../../audits/dependency-deep-audit.md).

| ID      | Level  | Rule                                                                                                                                                                                                                                                | Why                                              | Verified by                |
| ------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------- |
| R-DEP-1 | MUST   | Before adding a package, check in order: code already in the repo → native APIs (React, Next.js, the Web Platform, `Intl`, `fetch`, `<dialog>`) → installed dependencies → a few lines of code. Add a package only when none of the four is enough. | Every package is maintenance and security cost.  | `review`                   |
| R-DEP-2 | MUST   | No state management library (Zustand, Redux…) until client state is genuinely shared across several UI branches. Local state uses `useState`; filters/pagination use the URL; server data uses Server Components.                                   | No current use case needs one.                   | `review`                   |
| R-DEP-3 | MUST   | No Axios or other HTTP client: use `httpRequest`/`backendRequest` (`src/lib/api/`). No second UI library. No TanStack Query until there is a client-side reading need (polling, infinite scroll, autocomplete).                                     | Duplicates existing capabilities.                | `review`                   |
| R-DEP-4 | MUST   | Every new package is justified in the change description: the need, rejected alternatives, peer dependency compatibility (`pnpm peers check`), bundle impact (measured, not guessed).                                                               | The decision can be reviewed later.              | `human`                    |
| R-DEP-5 | MUST   | pnpm only (version in `packageManager`). Every dependency change ships with `pnpm-lock.yaml`; CI installs with `--frozen-lockfile`.                                                                                                                 | Reproducible builds.                             | `ci`                       |
| R-DEP-6 | MUST   | No major upgrades (Next.js, React, TypeScript, ESLint…) in the same change as a feature. No `pnpm.overrides` without a compatibility analysis.                                                                                                      | A major upgrade is a project of its own.         | `review`, `human`          |
| R-DEP-7 | SHOULD | After a dependency change: `pnpm audit --prod` is clean and `pnpm peers check` reports no issues.                                                                                                                                                   | Keeps the runtime free of known vulnerabilities. | `ci` (`pnpm audit --prod`) |
